# 1920×1017 版面（1920×1080 螢幕最大化）

> 座標 = `gui.sh shot` 截圖座標（客戶區 1920×1017 → 截圖 **960×508**，一樣是 `-Scale 2`）。索引見 [README.md](README.md)。
> 其他 `ui/*.md` 的座標都是 2880×1659（截圖 1440×830）版面，**不能直接拿來用**；這份是另外加的一套，原本的不動。

## 怎麼判斷用哪一套
- `bash tools/gui/gui.sh info` → `client=1920x1017 ... shot=960x508` 就用這份。
- `uv run --no-project python tools/gui/layout.py` 印出目前版面；`walk.py`、`stat.ps1` 會自己判斷，不用設定。
- 遊戲沒開時想用 1920×1017 試算：`PSA_LAYOUT=1920x1017 uv run --no-project python tools/gui/walk.py --plan ...`

## 換算規則（只用來估計，能量就直接量）
**地圖畫面（走路的每格位移）依寬度縮放 ×0.667**（1920 ÷ 2880，實測）；**UI 依高度縮放 ×0.613**（1017 ÷ 1659），並貼著畫面邊緣對齊：
- 靠左上的元件：`新 ≈ 舊 × 0.613`
- 靠右的元件：`新x ≈ 960 − (1440 − 舊x) × 0.613`；靠下的元件：`新y ≈ 508 − (830 − 舊y) × 0.613`
- 置中的面板（傳送面板、對話框、背包…）：`新 ≈ 中心 + (舊 − 舊中心) × 0.613`，中心是 (480,254) / 舊 (720,415)
- 實測誤差約 2～5 px（例：傳送鈕換算 899,40，實際 905,38）。按鈕夠大時通常點得到，小按鈕先截圖確認。

## 工具支援狀態
| 工具 | 1920×1017 | 說明 |
|---|---|---|
| `gui.sh` shot / click / key / pixel… | ✅ | 本來就照視窗大小縮放，座標用 960×508 截圖座標 |
| `gui.sh waitstill` | ✅ 實測 | 取樣點改成依客戶區等比例縮放（原本寫死 2880×1659，1920×1017 會報 GetPixel 超出範圍） |
| `stat.ps1`（OCR 讀 HUD） | ✅ 實測 | 等級、HP、血條 / 魔條 %、寵物、地圖、座標穩定讀得到；讀不到數字會換放大倍數重試。**MP 兩位數時常回 null**（Windows OCR 讀不出短數字）→ 看 `mpPct`。地圖名折兩行時的備用區域是換算值，未實測 |
| `walk.py` 找路 / 走路 | ✅ 實測 | 31401 奇努伊的海底通路：3 / 5 / 6 / 8 格與多段路線都準確到達。`TILE_X/Y` = (21.2, ∓15.2) 由走路前後截圖比對量出；引子 `PRIMER_XY` 點了無副作用（換地圖後吃第一下的情況未測）。找路失敗的兩次都是通行格資料的障礙邊緣不準（冰岩、水邊），不是座標問題。常數在 walk.py「1920×1017 版面」區塊 |
| `walk.py` 點 NPC（`npc_steps` / `talk_npc`） | ✅ 實測 | `NPC_DY` -19、對話框棕底 `SIG_NPC_DIALOG` 用醫院小護士量的；別的 NPC 對話框版面不同時自己給 sig |
| `heal.py` | ✅ 實測 | `heal.py --spot 海主人隧道`：關遇敵 → 傳送薩姆吉爾 → 醫院小護士補血 → 傳回 31401:91,29 → 開遇敵，一次成功 **18.2 秒**。常數在 heal.py「1920×1017 版面」區塊；練級傳送除了海主人隧道，其他目的地座標是從截圖量的、沒傳過 |
