### 追蹤列表標題辨識（`tools/gui/ocr.ps1` + quest.py `track_task()`）
- ocr.ps1：`ocr.ps1 X Y W H [-Zooms 2,3,4,5,6,7] [-Dark 150]`（截圖座標）→ JSON 每行 `{text,x,y,zoom}`。深色字二值化（max(R,G,B)<150）後交給 Windows 內建 OCR（zh-Hant）。
- 二值化已改 LockBits（2026-10-10，輸出與舊 GetPixel 版逐位元組相同，`test_binarize.py`）：`-Zooms 2..7` 讀追蹤列表約 4.3 s → 1.1 s（一次性）→ 0.49 s（常駐 server，`PSA_GUI_SERVER=1`）（WSL 實測，同時段 A/B 中位數）。
- **Windows OCR 對同一張圖換放大倍數，結果差很多**（有時整行讀不到、有時只讀到「書乛」「-轉)」之類殘字）。所以一次跑放大 2～7 倍，把 y 相近的行併成一格，比對時任一種讀法符合就算。比對 = 去掉括號版本字尾後，完整包含或相似度 ≥ 0.75。實測：「黃金羚羊之謎」整輪都能認出；個別倍數會讀成殘字，約 2～3 倍數內至少一個讀對（約 2.7 秒 / 次）。
- OCR 區域 `LIST_BOX = 75,270,260,180`；標題中心 y > 425（被面板裁掉一半）不點；點擊 = 標題中心 y + 16、x 205。
- 流程：先看目前這一頁（多半就在）→ 往下捲（`drag 200 420 200 300`，≈ 1 格）到盡頭 → 再往上捲到頂；每次捲完等 1.4 秒；**是否到盡頭用像素取樣判斷**（比 OCR 穩）。找到才點，找不到回報（沒領過獎勵時連續 2 輪都找不到才退出碼 5，避免剛換圖 / 標記剛出現的誤判）。
- 對話框 / 戰鬥 / 領獎跳出來時追蹤列表被蓋住（OCR 讀成空）→ track_task 每輪先確認仍是主畫面，不是就交回主迴圈，不當成找不到。
- 一輪完整搜尋（頁面 3 頁左右）約 20～30 秒；每步巡路後都要重搜，所以比以前慢，但不會點錯任務。
