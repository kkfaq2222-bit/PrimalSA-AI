## 單人逃跑解任務（`quest.py --solo` / `--fight`，2026-10-10；流程見 `/psa-quest-solo` skill）
目的：任務 NPC 會被隊伍裡的人擋 / 路上怪太強時，用「單人跑路 → 到 NPC 停下 → 一鍵組隊 → 對話 / 打」的風格，不靠原地遇敵練功等級硬衝。
- **完整戰鬥畫面的按鈕（實測 DKB0，遇敵地圖 11001，2026-10-10）**：下指令階段右上有 7 格指令框（截圖座標 1048～1420 × 22～220），第 1 排 4 格 y≈75（攻擊 1090 / 技能 1180 / 捕捉 1280 / 道具 1370），第 2 排 y≈168：**逃跑（跑步小人）1283,168**（點了角色頭上冒「Escape!」泡泡，**實測 8 次都有效**；失敗會留在戰鬥，下一回合再按）。上方「N回合 / 剩餘時間 84」倒數，右側 **自動戰鬥鈕 1380,600**（點一下切換，日誌「你已開啟 / 關閉自動戰鬥」，與外掛 ASS 的自動戰鬥是同一個開關）。
- **下指令階段 vs 播放中**：下指令時右上指令框存在；播放中（「播放中」標籤）框消失。quest.py `SIG_CMD`：1283,168 (143,119,102) / 1100,170 (139,117,98) / 1100,60 與 1250,60 (187,161,131) / 1060,200 (133,100,72)，容差 25，五點全符合 = 下指令階段（只在完整戰鬥時判）。播放中這幾點是地面顏色。
- **自動戰鬥開著時不會停在下指令階段**（指令框直接不出現，立刻「播放中」）；要按逃跑必須先把外掛的自動戰鬥關掉（和原地遇敵 / 自動逃跑 / 快速戰鬥）。**自動戰鬥鈕「關」= 靜止紅色圖示**（1380,600 ≈ (75,29,16)、1375,605 ≈ (249,181,100)，連讀 8 次不變）；「開」是擺動的刀劍動畫，顏色不固定 → 只能判斷「是不是關」（`SIG_AUTO_OFF`，容差 20），所以 `--fight` 是「看到關才點、3 秒內不重點」。
- **`--solo`**：每 1.5 秒（預設，可用 `--every` 改）判斷一次；完整戰鬥 + 下指令階段 → 按逃跑（兩次按之間 ≥ 1.2 秒）；只看到 VS 牌（快速戰鬥還開著）→ 無法逃跑，印警告一次；**出現 NPC 對話框 → 存圖、`{ESC}` 關閉（不按任何選項）→ 退出碼 20「到達 NPC」**。實測（11001 洞窟，加 `--no-track`，原地遇敵開著，45 秒）：連續 6 場全部在戰鬥開始 1 秒內按逃跑、約 2 秒回主畫面，每場只按一次。

## 檢測方針（使用者指定，2026-10-10；quest.py 的主畫面處理）
優先順序：**對話框 / 獲得物品 / 戰鬥處理 > 黃色「?」> 依 --task 點追蹤**。
1. **畫面上有黃色「?」（NPC / 物件頭上的任務標記）→ 優先點它，點的是「問號下面」（NPC 身體），不是問號本身。** 點完等最多 8 秒看對話框出現（隊伍自己走過去，途中沒有 Auto Walking 字樣）。

### 追蹤列表標題「圖片樣板比對」（`tools/gui/titlematch.py` + `titlematch.ps1`，2026-10-10；比 OCR 快 20～40 倍，本機運算不上傳）

### Clef 加速層（`tools/gui/clef.py`，2026-10-10；Cloudflare Workers AI，會上傳遊戲截圖）
只是「加速層」：失敗一律退回原本的規則 / OCR，不卡住、不讓 quest.py 失敗。實驗數據見 `notes/clef-eval.md`。
- **接點 1（unknown）**：`read_screen` 判不出（state=unknown）且 netwatch 先排除登入畫面 / 網路異常提示後，才截圖（縮 960 寬）問 Clef-flash「場景 + 有沒有驗證視窗」；top < 0.85 升級 Clef 複核。
  場景判「載入畫面 / 戰鬥中」（p >= 0.85 且 verify <= 0.05）→ 不算「不認得」（連續最多 20 次，之後照舊 3 次停手）；其他場景只記 log，仍走原本 3 次停手。
- **驗證視窗只多一道警報**：確定性規則（3 次 unknown 停手、退出碼 2）完全保留；Clef 任一次呼叫 verify > 0.05（或場景判「答題或驗證視窗」）→ 立刻存圖停手（退出碼 2）。模型說「沒有」絕不放行任何事。尚無真驗證視窗正例，抓不抓得到未驗證。

### 追蹤列表標題辨識（`tools/gui/ocr.ps1` + quest.py `track_task()`）
- ocr.ps1：`ocr.ps1 X Y W H [-Zooms 2,3,4,5,6,7] [-Dark 150]`（截圖座標）→ JSON 每行 `{text,x,y,zoom}`。深色字二值化（max(R,G,B)<150）後交給 Windows 內建 OCR（zh-Hant）。
- **Windows OCR 對同一張圖換放大倍數，結果差很多**（有時整行讀不到、有時只讀到「書乛」「-轉)」之類殘字）。所以一次跑放大 2～7 倍，把 y 相近的行併成一格，比對時任一種讀法符合就算。比對 = 去掉括號版本字尾後，完整包含或相似度 ≥ 0.75。實測：「黃金羚羊之謎」整輪都能認出；個別倍數會讀成殘字，約 2～3 倍數內至少一個讀對（約 2.7 秒 / 次）。
- OCR 區域 `LIST_BOX = 75,270,260,180`；標題中心 y > 425（被面板裁掉一半）不點；點擊 = 標題中心 y + 16、x 205。
- 流程：先看目前這一頁（多半就在）→ 往下捲（`drag 200 420 200 300`，≈ 1 格）到盡頭 → 再往上捲到頂；每次捲完等 1.4 秒；**是否到盡頭用像素取樣判斷**（比 OCR 穩）。找到才點，找不到回報（沒領過獎勵時連續 2 輪都找不到才退出碼 5，避免剛換圖 / 標記剛出現的誤判）。
- 對話框 / 戰鬥 / 領獎跳出來時追蹤列表被蓋住（OCR 讀成空）→ track_task 每輪先確認仍是主畫面，不是就交回主迴圈，不當成找不到。
- 一輪完整搜尋（頁面 3 頁左右）約 20～30 秒；每步巡路後都要重搜，所以比以前慢，但不會點錯任務。
